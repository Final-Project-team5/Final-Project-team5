# 제안: 폰트 색상 팔레트 방식 (진우님 요청 검토)

> 상태: 제안 문서(구현 없음). 팀 합의 후 담당/범위 확정.
> 작성: 문구 모델 관점의 아이디어 제안. 렌더링은 이미지 파트, UI는 프론트 소관.

## 1. 검토 요청 배경

진우님 요청: 포스터의 문구(폰트) 색상을 "배경색과 조합되는 팔레트 사전 구성"으로
할지 "사용자 직접 커스텀"으로 할지 검토.

## 2. 선택지 비교

| 방식 | 장점 | 단점 |
|---|---|---|
| A. 사전 팔레트 (서버 결정적 매핑) | 결과 품질 일정, 사용자 부담 0, 구현 단순 | 자유도 낮음 |
| B. 사용자 커스텀 (컬러 피커) | 자유도 최대 | 소상공인이 색 조합에 서투름, 가독성 망가진 결과가 그대로 나감, UI 복잡 |
| C. 배경색 기반 자동 산출 | 배경과 항상 어울림 | 구현 복잡(배경 분석), AI 배경은 색이 다양해 단색 추출이 애매 |

## 3. 제안: A를 기본으로, 이미 승인된 패턴 재사용

핵심 아이디어는 **purpose→aspect_ratio와 같은 구조(서버 결정적 매핑)를 색에도
적용**하는 것. 팀이 이미 승인한 패턴이라 리뷰/연동 비용이 낮다.

- 매핑 키: category + tone (문구 생성 시 이미 받고 있는 값 — 추가 질문 불필요)
- 서버가 spec에 팔레트 후보 2~3개를 실어 내려줌. 프론트는 목록 그대로 노출,
  사용자는 고르기만 함(커스텀보다 단순, 사전 구성보다 선택권 있음).
- 각 후보는 {font_color, outline_color} 쌍. 이미지 파트는 받은 값 그대로 렌더.

### 초안 매핑 (예시 값 — 디자인 감수 필요)

| tone | 후보1 | 후보2 | 비고 |
|---|---|---|---|
| warm | 크림 화이트(#FFF8F0) + 브라운 외곽(#5C4033) | 딥브라운(#4A342A) | 밝은/어두운 배경 대응 쌍 |
| energetic | 화이트(#FFFFFF) + 레드오렌지 외곽(#E8491D) | 옐로(#FFD93D) + 다크 외곽 | 고채도 배경 대비 |
| luxury | 골드(#C9A227) + 딥그린 외곽(#1B3A2F) | 아이보리(#F5EFE0) | 저채도 배경 전제 |
| simple | 차콜(#2B2B2B) | 화이트(#FFFFFF) | 외곽선 최소화 |

- 배경 밝기(단색/그라데이션이면 서버가 알고 있음)에 따라 후보 순서를 뒤집어
  주면(밝은 배경이면 어두운 후보 먼저) C안의 장점 일부를 공짜로 얻음.
- AI 배경은 색 분석이 필요하므로 1차 범위 제외, 기본 후보만 제공.

### 가독성 가드 (덤으로 얻는 품질)

후보 산출 시 배경색 대비비(WCAG 기준 4.5:1)를 서버에서 검사해, 대비가 부족한
후보는 자동 제외하거나 외곽선을 강제. "읽히는 포스터"를 구조로 보장.

## 4. 역할 분담 제안 (경계 준수)

- 문구 모델: category+tone 기반 팔레트 후보 결정 로직(순수 함수, 비용 0)까지 가능
- 이미지 파트(지우님): font_color/outline_color 렌더 반영 (기존 파라미터에 색만 추가)
- 프론트(소원님): 후보 노출 UI. 브랜드 리뉴얼(애드지니 보라/파랑)과는 별개 —
  이건 포스터 출력물의 색이지 서비스 UI 색이 아님. 규제 배지 색 분리 원칙과 동일.

## 5. 미정 (팀 결정 필요)

- 방식 채택 여부(A 기본 + 후보 선택형), 커스텀(B)을 2차로 열지
- 담당 배분: 매핑 로직 위치(문구 서버 vs 포스터 서버)
- 팔레트 값 디자인 감수, 22일 동결 내 반영 범위
