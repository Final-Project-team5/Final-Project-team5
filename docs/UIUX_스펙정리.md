# 광고 콘텐츠 생성 서비스 — UI/UX 플로우 정리

> 지금까지 팀 내에서 확정된 정보를 바탕으로 정리한 화면/흐름 스펙입니다.

---

## 1. 서비스 컨셉 (확정)

- **핵심 차별점**: 예쁜 문구가 아니라 **법적으로 문제없는 광고 문구**를 생성
- **규제 필터링**: 표시광고법·식품표시광고법·화장품법 등 금지/주의 표현 자동 검사. 생성 → 검증 → block/warn 플래그 → 통과한 것만(또는 경고와 함께) 출력. 룰 사전은 계속 확충 예정 (도혁님)
- **대표 데모 사례**: 건강기능식품/화장품 과장 광고 (예: "아토피 치료되는 크림" → block)
- **타깃 도메인**: 우선 **푸드 / 뷰티 / 굿즈** 3개 업종 (PM 확정, 8/4). 패션은 우선순위에서 제외.
- **K-컬처 정체성**: 이번 1차 서비스에서는 반영하지 않음 — 추후 고도화 단계에서 다룰 요소로 보류 (PM 확정)
- **성능 우선순위**: 모델 퀄리티 >>> 응답 시간 (무거운 모델·다단계 파이프라인 허용)
- **입력 방식**: **챗봇(도우미)이 메인 인터페이스** — 순차 질문형 흐름으로 정보를 채움 (8/5 최종 확정, 아래 참고)
- **AI 생성물 표시 의무 (인공지능기본법 제31조)**: 생성형 AI 결과물에는 AI로 생성됐다는 사실을 표시해야 함. 이미지 내 표기(지우님 후처리)와 화면 고지(소원님 프론트) 두 군데로 나눠 대응 — 상세는 4장 참고

## 2. 담당 범위 (확정)

| 파트 | 담당 |
| --- | --- |

| 포스터 이미지 생성 (2단계 파이프라인) + AI 생성물 이미지 내 표기 | 황지우 |

## 3. 전체 사용자 플로우 (메인형 챗봇 확정, 8/5)

> 카드/칩 직접 클릭형(서브 챗봇 병행)과 챗봇 메인형 두 버전을 목업으로 비교한 결과,
> **메인형이 선택 과정이 간결하고 카테고리 밖 선택지 등록도 편리하다는 PM 피드백에 따라 메인형으로 확정.**

```
[홈 화면]
좌측 사이드바: 로고, [새로 만들기] 버튼, "오늘의 광고 규제 한 줄"(순환 티커), AI 생성물 사전 고지 문구
메인 영역: "오늘은 어떤 광고를 만들어볼까요?" + 예시 카드(정적 이미지, 자동 스크롤 티커) + [새로 만들기]
        │
        ▼ [새로 만들기] 클릭
챗봇이 순서대로 질문 (진행률 n/9 단계로 표시), 각 질문은 선택지 4개 + 기타(직접 입력) 제공
  1) 어떤 업종이신가요? (푸드/뷰티/굿즈 + 기타)
  2) 어떤 제품/가게인가요?
  3) 원하시는 포스터 느낌은 어떤가요?
  4) 강조하고 싶은 점은 무엇인가요? (복수 선택 가능)
     └─ 선택 즉시 바로 5)번 질문으로 자동 연결 (중간 확인 버튼 없음, 8/5 PM 피드백 반영)
  5) 추가로 요청하실 사항이 있나요? (자유 입력, 선택)
     └─ [이 내용으로 완료] 버튼으로 마무리
        │
        ▼
"제공해주신 정보를 바탕으로 제작 중입니다" 로딩 → 문구/이미지 생성 시작
        │
        ▼
문구 생성 + 규제 검증  ← 도혁님 API (/generate/copy)
     ├─ 통과 → 문구 확정
     └─ block/warn → 대체 문구 제안 또는 사용자 직접 수정 → /validate/copy로 재검증
        │
이미지 1단계 생성 (가벼운 모델, 시안 3장 고정)  ← 지우님 API (/generate/drafts)
     [로딩 A] "초안 생성 중" (하위 체크: 키워드 분석 중 / 문구 초안 생성 중)
        │
시안 3장 중 하나 선택
        │
문구 위치 자유 조정 (드래그, 좌표 0~1 비율) + 폰트 크기 프리셋(작게/보통/크게) 선택
     → 서버 호출 없이 프론트에서 CSS로 실시간 미리보기
     → [완성하기] 누를 때 딱 한 번 최종 좌표+폰트크기를 서버에 전송
     → 문구 자체의 줄바꿈/형태는 도혁님 문구 생성 단계에서 이미 고정되어 옴 —
        프론트은 위치·크기만 결정, 텍스트 형태 자체는 관여하지 않음
        │
이미지 2단계 고품질화 (선택한 시안 + 문구 + 위치/크기 반영)  ← 지우님 API (/generate/refine)
     [로딩 B] "고품질화 중" (하위 체크: 이미지 고품질화 중 / 문구 배치 최적화 중)
     (지우님 파이프라인 내부에서 제품합성·업스케일·문구삽입·크롭·AI생성물 워터마크까지 완료,
      자동 줄바꿈으로 이미지 밖 이탈 방지)
        │
최종 결과 표시 (이미지 + 문구 + 규제통과 배지 + "AI 생성 콘텐츠" 캡션)
        │
용도별 사이즈 선택 (SNS 카드뉴스 / 배너 / 상세페이지)
        │
다운로드
```

**중요**: 로딩이 총 2번(초안 생성 → 고품질화) 발생 — UI에서 이 두 단계를 명확히 구분해서 보여줘야 사용자가 "왜 또 기다리지" 하고 이탈하지 않음.

**⚠ 주의 — 실제 개발 시 놓치지 말 것**
- **제품 사진 업로드 기능**: 목업(HTML)에는 빠져있으나 실제 구현 필수. 있으면 inpaint, 없으면 text2img 모드로 자동 분기. 챗봇 흐름 중 자연스러운 시점(예: 2번 질문 근처)에 삽입 위치 결정 필요
- 문구 위치 조정 화면에서 위치에 따라 텍스트 레이아웃(세로/가로 등)이 바뀌는 동작은 **목업(HTML) 한정 임시 동작**이며 실제 구현 대상 아님 — 문구 형태는 도혁님 쪽에서 고정되어 내려옴

### 3-1. 챗봇 API 구조 (도혁님, 8/5 확정)

```
POST /suggest/options (또는 동일 계열 엔드포인트)
{ step, spec }  ← spec은 프론트가 들고 다니는 stateless 값 (포스터 API와 동일 패턴)
```
```
{
  step, total_steps,          // 진행률 표시용 (n/9 단계)
  question,                    // 이번 질문
  options: [...],              // 선택지 4개 (기타는 프론트에서 추가)
  spec: { keywords: [...] },   // 지금까지 채워진 값 → 메인 키워드 칩에 바로 매핑 가능
  confirm_message,             // 선택 종류에 맞는 확인 문구 (서버가 생성)
  done: true | false           // 마지막 단계 완료 시 true
}
```
- `target_slots` 옵션 추가 예정 — 특정 항목만 지정해서 물어보는 것도 가능해지지만, **현재는 메인형(1단계부터 순서대로)으로 확정**했으므로 이 옵션은 사용하지 않음. 추후 서브 보조 기능이 필요해지면 재검토
- `step`/`spec`을 요청에 같이 보내면 중간 단계부터 시작 가능한 구조지만, 뒤로 가서 답변을 바꾸는 흐름을 지원하려면 서버가 "이미 지난 단계 재요청"도 정상 처리하는지 확인 필요 (미확인 — 확인 필요)
- `COPY_MOCK` 모드 있음 — API 키/실 모델 없이도 프론트 연동 테스트 가능

## 4. 화면별 상세

### 화면 -1 — 홈
- 좌측 고정 사이드바: 서비스 로고, [+ 새로 만들기] 버튼
- "오늘의 광고 규제 한 줄" — 짧은 규제 상식 카드, 여러 개가 몇 초마다 페이드 인/아웃되며 순환 (최근 작업 목록 대체 콘텐츠, URL/저장소 불필요)
- 하단에 AI 생성물 관련 사전 고지 문구 상시 노출 (예: "이 서비스는 생성형 AI로 문구와 이미지를 자동 생성합니다")
- 메인 영역: 헤드라인("오늘은 어떤 광고를 만들어볼까요?") + 설명 + [+ 새로 만들기]
- 우측: 예시 결과 카드 — 실제 모델 결과물 중 선택한 정적 이미지, 세로 방향 자동 스크롤(티커) 효과로 계속 흘러가며 노출. 카테고리(푸드/뷰티/굿즈)별로 순환
- **최근 작업 목록은 제거** — 이력 저장 기능(URL 방식) 필요, 1차 서비스에서는 보류 (7장 참고)

### 화면 A — 챗봇 진행 화면 (구 카테고리·키워드·문구 입력 단계 통합)
- 챗봇이 5개 질문을 순서대로 진행, 답변은 대화 말풍선으로 누적 표시
- 각 질문: 선택지 4개(카드/버튼) + "기타" 선택 시 텍스트 입력칸 노출
- 4번(강조점, 복수 선택) 답변 즉시 5번 질문으로 자동 연결 (중간 확인 버튼 없음)
- 5번(추가 요청, 자유 입력) 답변 후 [이 내용으로 완료] 버튼으로 마무리
- 상단에 진행률 표시 (n/9 단계)
- **제품 사진 업로드는 이 흐름 중 반영 필요** (구현 시 놓치지 말 것)

### 화면 B — 문구 생성 결과 (규제 검증 반영)
- **통과 시**: 생성된 문구 + "규제 검증 통과" 배지
- **block/warn 시**: 걸린 사유 간단 표시 + 대체 문구 제안 + "이 문구로 계속하기" 버튼
- **직접 수정 옵션**: 사용자가 문구를 직접 편집할 수 있는 입력창 제공 → 수정 완료 시 `/validate/copy`로 재검증 → 재차 block이면 다시 안내
- 이 화면에서 문구가 확정된 후에만 이미지 생성 단계로 진행

### 화면 C — 이미지 초안 선택 (1단계 결과)
- 시안 **3장 고정** 그리드로 표시 (base64 이미지 직접 렌더링)
- 각 시안 클릭 시 선택 표시(테두리 강조 등) + 선택한 시안을 화면 하단(또는 별도 영역)에 크게 확대해서 보여줌
- 로딩 중에는 스켈레톤 카드로 자리 확보 (레이아웃 흔들림 방지)
- 다시 생성하기(재시도) 옵션도 함께 제공

### 화면 D — 문구 위치·크기 자유 조정
- 선택한 시안(문구 없는 배경 상태) 위에서 사용자가 문구를 자유롭게 드래그하여 위치 지정
- **폰트 크기: 작게/보통/크게 3단계 프리셋 확정** (8/5)
- 드래그하는 동안은 서버 호출 없이 **프론트 CSS로 실시간 미리보기**만 처리 (즉각 반응)
- [완성하기] 버튼을 누를 때 딱 한 번만 최종 좌표(x, y — 0~1 비율)와 폰트 크기를 담아 서버에 전송
- 문구의 줄바꿈/형태 자체는 도혁님 쪽에서 고정되어 옴 — 위치 이동에 따라 형태가 바뀌는 동작은 없음
- `style`은 이번 단계에서는 `plain` 고정 — 별도 UI 없음 (추후 `bar` 옵션 추가 시 여기에 토글 추가)
- **[완성하기] 클릭 후 별도의 "고품질화 중" 로딩 화면(로딩 B)으로 전환** — 시안 선택 때의 로딩(로딩 A)과 시각적으로 구분되어야 함
- **/generate/refine 요청 실패/타임아웃 시에도 재시도 버튼 제공** (1단계 재시도와 별개로 구현)

### 화면 E — 최종 결과
- 고품질화된 최종 이미지 + 확정 문구 표시
- 규제통과 배지 유지 표시
- **"AI 생성 콘텐츠" 캡션 표시** (AI기본법 제31조 대응) — 이미지 내부 워터마크(지우님)와 별개로 화면 텍스트로 노출
- 용도별 사이즈 토글 (SNS / 배너 / 상세페이지) — 크롭은 지우님 파이프라인 결과물 중 해당 규격을 선택해서 보여주는 방식으로 처리 (프론트에서 직접 크롭 연산 안 함)
- 다운로드 버튼 (base64 → blob 변환 후 다운로드)
- "처음부터 다시 만들기" 버튼으로 홈으로 복귀

## 5. 데이터 흐름 (현재 확정된 API 기준)

### 포스터 모델 (지우님) — 확정, 2단계 엔드포인트 분리

**1단계 — 시안 3장 생성**
```
POST /generate/drafts
{
  "mode": "inpaint" | "text2img",
  "image": "<base64>",     // inpaint일 때만 전달
  "prompt": "배경 설명",
  "num_images": 3
}
```
```
{
  "drafts": [
    { "id": "d1", "image": "<base64>", "seed": 12345 },
    { "id": "d2", "image": "<base64>", "seed": 67890 },
    { "id": "d3", "image": "<base64>", "seed": 24680 }
  ],
  "meta": { "elapsed": 9.8, "model": "sd15" }
}
```

**2단계 — 선택 시안 고품질 렌더링 + 문구 합성**
```
POST /generate/refine
{
  "draft_image": "<base64>",   // 1단계에서 사용자가 선택한 시안을 그대로 재전송
  "prompt": "배경 설명",
  "text": {
    "headline": "...",       // 도혁님 문구 모델 결과 (20자 내외, 형태 고정되어 전달됨)
    "sub": "...",             // 도혁님 문구 모델 결과 (30자 내외, 형태 고정되어 전달됨)
    "position_x": 0.6,        // 0~1 비율, 프론트에서 자유 드래그로 결정
    "position_y": 0.15,       // 0~1 비율
    "font_size": 32,          // 3단계 프리셋(작게/보통/크게)에 매핑된 값
    "style": "plain" | "bar"  // 우선 plain 고정
  }
}
```
```
{
  "image": "<base64>",
  "meta": { "elapsed": 12.3, "model": "sdxl", "seed": 67890 }
}
```

**구현 시 유의할 점**
- **서버가 세션을 저장하지 않는 stateless 구조** — 프론트가 1단계 응답에서 사용자가 선택한 시안의 `image`(base64)를 상태로 들고 있다가 2단계 요청 때 `draft_image`로 그대로 다시 보내야 함
- **문구 중계 역할**: 도혁님 문구 모델 결과(`headline`, `sub`)를 프론트가 받아서 `text` 필드에 담아 포스터 refine API로 넘겨줌. 프론트는 문구 내용/형태에 관여하지 않고 위치·크기만 결정
- **위치는 좌표(x,y 비율) 방식**, **폰트 크기는 3단계 프리셋** (8/5 확정) — 프론트가 드래그 UI + CSS 미리보기 구현, 서버 요청은 완성 시 1회만
- **글자 수 제한(headline 20자/sub 30자)은 프론트가 자르지 않음** — 문구 생성 단계(도혁님)에서 자동 축약 1회 처리, 그래도 초과 시 `over_limit` 플래그로 하향 전달
- 결과는 **base64**로 수신 (URL 방식은 추후 이력 저장 기능 필요 시 재검토 — 7장 참고)
- **AI 생성물 워터마크**: 지우님 후처리 단계에서 이미지 하단 모서리에 반투명 표기 처리 (프론트 작업 아님)

**챗봇(메인 흐름) 순차 질문** (8/5 최종 확인, 도혁님)

실제 필수 필드는 `message` 하나뿐. 프론트가 매 요청마다 챙겨야 하는 건 `message`(사용자가 고른/입력한 값) + `step`(직전 응답의 `next_step` 그대로) + `spec`(누적 상태, 계속 들고 다님) 세 개뿐이다.

```
POST /suggest/options

// 1단계 시작
{ "message": "푸드" }

// 2단계 이후
{ "message": "떡볶이", "step": 2, "spec": { "category": "food" } }
```
```
{ step, next_step, total_steps, question, options: [...], spec, confirm_message, done }
```

**필드별 설명**
- `message` (필수) — 사용자가 선택지를 골랐으면 그 텍스트, "기타"로 직접 입력했으면 그 문장 그대로
- `mode` (기본값 `"fixed"`) — 안 보내면 고정 5단계 흐름으로 동작. 메인형 확정된 지금 방향에서는 생략(기본값 사용)
- `step` (기본값 1) — 응답으로 내려온 `next_step`을 그대로 다음 요청의 `step`에 넣어주면 됨
- `spec` — 서버가 상태를 저장하지 않는 stateless 구조(포스터 API와 동일 패턴)라 프론트가 들고 있다가 매 요청에 같이 전송. 응답 `spec`에 병합되어 내려옴
- `history` — `auto` 모드(자유 대화형)에서만 사용. `fixed` 모드에서는 `spec`이 상태를 대신하므로 생략 가능
- `target_slots` — 특정 항목만 물어볼 때 사용(예: `["tone"]`). 메인 흐름에서는 생략. 서브 보조 기능 필요해지면 재검토 (7장 참고)

5단계까지 완료(`done=true`)되면 `/generate/copy` 요청으로 자동 연결됨. `COPY_MOCK` 모드로 키 없이도 프론트 연동 테스트 가능.

## 6. 엣지 케이스 / 예외 처리

| 상황 | 처리 방향 |
| --- | --- |
| 문구가 규제에 걸림(block/warn) | 대체 문구 자동 제안 또는 사용자 직접 수정 → `/validate/copy` 재검증 |
| 이미지 생성 실패/타임아웃 | 재시도 버튼 노출, 에러 원인은 사용자 친화적 문구로 (내부 에러 메시지 그대로 노출 X) |
| 제품 사진 없이 시작 | text2img 모드로 자동 전환, 사용자에게 별도 설명 불필요 |
| AI가 조리된 음식을 어색하게 생성 | 제품 사진 업로드(inpaint 모드)를 권장 문구로 유도해 실사 보존으로 우회 |
| 생성 시간이 예상보다 길어짐 | 로딩 화면에 대략적 진행 상태(초안 생성 중 / 고품질화 중) 구분 표시로 체감 대기시간 줄이기 |
| 문구가 길어서 이미지 밖으로 나갈 위험 | 프론트가 자르지 않음 — 도혁님 생성 단계 자동 축약 + over_limit 플래그 + 지우님 쪽 자동 줄바꿈으로 다중 방지 |
| 챗봇 답변을 뒤로 가서 바꾸고 싶을 때 | **이번 주 스코프에서 제외** — 1차 서비스에서는 미구현, 7장 보류 항목 참고 |
