# 규제 필터 실험 결과 정리 (전후 비교용)

> 목적: A/B 실험과 골드셋 회귀 테스트 결과를 파일로 남겨, 이후 룰 수정 시 전후 비교의 기준선으로 사용.
> 기준일: 2026-08-11 갱신 · 모델: gpt-5.4-mini · 측정: 룰 검사 기반(비용 0)
> 원자료: `eval/results/goldset_result.json`, A/B 상세 덤프 `ab_v2_detail.json`

---

## 1. A/B 실험 — 규제 지침 유무에 따른 위반율

### v1 (무자극 입력) — 실패, 설계 결함 확인
- A(규칙 없음)·B(규칙 있음) 모두 위반율 0%. 모델이 위반할 이유가 없는 입력이었음
  (GPT-5.4 Mini 안전정렬). → 설계 재구성.

### v2 (위반 유도 입력) — 12케이스 × 3시안 × 2그룹 = 72시안

| 그룹 | 위반율(block) | 경고율(warn) | 안전율 |
|---|---|---|---|
| A · 규칙 없음 | 2.8% (1건) | 19.4% (7건) | 97.2% |
| B · 규칙 있음 | **0.0%** | **8.3% (3건)** | 100% |

- 규제 지침 적용 시 위반 1→0건, 경고 7→3건 감소. 핵심 신호는 경고율(19.4%→8.3%).

## 2. 골드셋 회귀 테스트 — 룰 정확도

라벨링된 케이스(block/warn/safe)로 룰의 미탐·오탐·등급오류를 수치화. 룰 수정 시마다 회귀 감시.

### 지표 정의 (강사님, PM 리뷰 반영)
이진 지표(flagged vs safe)만 보면 block/warn 등급 오류가 가려진다는 지적을 반영해,
**등급까지 정확히 맞췄는지(라벨 정확일치율, predicted==expected)를 1차 지표**로 둔다.
탐지 precision/recall은 참고용. 3-클래스 혼동으로 등급 오류(warn↔block)를 양방향으로 감시한다.

**대표 성능 수치는 HOLDOUT 라벨 정확일치 90.6%로 본다.** 전체(81) 96.3%는 TRAIN 100%가
섞여 희석된 값이라 대표 지표로 쓰지 않는다. TRAIN 100%는 룰 수정이 반영됐는지 확인하는 값이지
성능이 아니다(순환). 한 번도 안 본 HOLDOUT만 실제 성능을 대표한다.

### 진행 경과 (전후)

| 시점 | 케이스 | 라벨 정확일치 | 탐지 P / R / F1 | 미탐 | 오탐 |
|---|---|---|---|---|---|
| 보정 전(baseline) | 32 | — | 88.2 / 83.3 / 85.7 | 3 | 2 |
| 보정 후 | 68 | 98.5% | 100 / 97.8 / 98.9 | 1 | 0 |
| **경계 케이스 편입(현재)** | **81** | **96.3%** | **95.7 / 97.8 / 96.7** | 1 | 2 |

> "보정 후" 단계의 100% precision은 **safe 케이스가 명확해서** 나온 값이었음(강사님 "지표가 너무
> 높아 오히려 의심" 지적). 위반과 헷갈리는 **경계 정상 문구 13개를 편입**하니 오탐 2건이 드러나
> precision이 95.7%로 내려감. 단, 이 13개는 **오탐을 유도하도록 일부러 설계한 케이스**라 실제
> 서비스 입력 분포를 대표하는 값은 아니다. 따라서 95.7%는 **보수적인 하한선(worst-case)**으로 읽는다.

### train/holdout 상세 (과적합 방지)

| split | n | 라벨 정확일치 | 탐지 P / R / F1 |
|---|---|---|---|
| TRAIN(튜닝 대상) | 49 | 100% | 100 / 100 / 100 |
| **HOLDOUT(미노출)** | 32 | **90.6%** | 86.7 / 92.9 / 89.7 |
| 전체 | 81 | 96.3% | 95.7 / 97.8 / 96.7 |

- TRAIN 100%는 튜닝 대상이라 당연한 값(순환). **실제 실력은 한 번도 안 본 HOLDOUT(라벨 정확일치 90.6%)**.
- 3-클래스 혼동상 warn↔block 등급 오류는 0건(현재). 지표는 발생 시 양방향으로 잡도록 수정됨.

### 남은 오류 (정직한 한계)
- **미탐 1건**: "면역 쑥쑥 올려주는 홍삼" — 정규식이 못 잡는 **의미 회피**.
- **오탐 2건**: "최고의 하루를 담은 다이어리", "완벽한 오후를 위한 캔들" — 제품을 최고/완벽이라
  단정한 게 아니라 하루·오후를 수식한 건데, 정규식이 **맥락을 몰라** '최고/완벽' 단어만 보고 잡음(둘 다 warn).
- 미탐·오탐 모두 **정규식이 맥락을 못 보는 같은 한계** → **LLM 검증 레이어(로드맵)** 필요성의 실측 근거.

## 3. 룰 한계 스트레스 (레드팀) 와 2차 레이어

의미회피 위반 11건을 별도 split(redteam, 대표 지표 미포함)으로 만들어 룰의 맹점을 노출.

- 룰 단독(goods 룰 보강 후): 11건 중 3건 포착(27%). 여전히 food/beauty 의미회피 8건은 놓침.
- 하이브리드(룰 → 경계 케이스만 LLM 2차) oracle 상한(완벽 판정 가정):
  - HOLDOUT: 90.6% → 100%(라우팅이 오류 3건 다 포착)
  - REDTEAM: broad 정책 100% / lexicon 정책 54.5%
- 라우팅 정책 트레이드오프: broad는 커버리지 높지만 정상 트래픽 에스컬레이션율 2배(비용).
- 상세 설계·수치·실행법은 `설계_LLM검증레이어.md`. LLM 실제 효과는 API 키 실측 예정.

> 레드팀은 자체 작성이라 포착 자체가 독립 검증은 아니다. 목적은 '룰이 구조적으로
> 못 잡는 유형'을 노출해 2차 레이어의 필요성과 라우팅 정책 근거를 확보하는 것.

## 4. 결론
- 규제 지침은 위반 유도 상황에서 위반·경고 표현을 실측으로 억제한다.
- 룰은 명백 위반을 잡는 1차 필터로 유효하나(라벨 정확일치 HOLDOUT 90.6%), **맥락 판단(의미 회피·문맥 최상급)은 못 한다.**
- 룰 수정은 골드셋 회귀로 안전 관리, holdout으로 과적합 감시, 경계 케이스로 오탐을 스트레스 테스트한다.
